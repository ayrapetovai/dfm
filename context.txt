# DFM — dotfile manager (Rust)

## What dfm is / main goals

Syncs dotfiles between a **target** dir (usually `$HOME`) and a **source** dir (a git repo like `~/dotfiles`). Commands: `init`, `add` (target→source), `pull` (source→target), `sync` (both directions, already-managed only), `merge`, `diff`, `forget`, `purge`, `ignore`, `paths`, `config`, `status`, `encrypt`, `decrypt`.

Core invariants:
- **Local only**: sync between two dirs on one machine; never talks to git servers/network/cloud. Git is used only by external commands (status header shows git branch); git commands are NOT embedded into dfm.
- **State-driven**: every decision comes from `state.toml` (`SyncTime{mtime, sha256}` per source-relative path), not from scanning alone. Content hash makes change detection deterministic.
- **Failure-safe**: atomic writes (sibling temp + `rename`), mutating ops are queued as task enums then executed in a final loop, state committed once at the end (all-or-nothing per run).
- **Deterministic output**: status entries sorted by path; `--porcelain`/`--short` formats are frozen (uncolored, never paged).
- **Encrypted sources** are stored as self-contained blobs (never plaintext in the source dir).
- **Root guard**: refuses to run with root privileges not obtained as the real root user (sudo/setuid); bypass via `DFM_ALLOW_ROOT` (any non-empty value).

Global flags: `-n/--dry-run`, `-v <0-3>` (1 brief default, 2 info, 3 debug), `-c <PATH>` alt config.

## Layout

`src/main.rs` dispatch + config/state loading; `src/cli.rs` clap Args/Command (`#[path]`-included by build.rs); `src/lib.rs` DfmError, Settings/Config/StateObject, path+ignore helpers, `list_directory`, `compare_files`, ProgressLine, unit tests; `src/crypt.rs` encryption; `build.rs` renders dfm.1 via clap_mangen; `src/commands/{add,pull,sync,merge,diff,forget,init,ignore,purge,config,paths,status,encrypt}.rs`; `src/commands/mod.rs` shared helpers.

## Key types & files (lib.rs)

- **DfmError**: `Io/Unsupported/NotFound/InvalidData/InvalidInput/Other`; helpers `other(msg)`, `is_permission_denied()`. `From<io/toml/regex/microxdg>`.
- **Settings/Config**: same fields, Config is optional TOML. `source_dir`/`target_dir` live ONLY in the state file, not config. `merge_tool_command` default `vimdiff {target} {source} {result}`; `diff_tool_command` default `vimdiff -M {target} {source}` (read-only).
- **StateObject**: `{source_directory, target_directory, syncs: HashMap<String, SyncTime>}`. Sync key = source-relative path; `validate_state_key` rejects `..`/absolute/drive components on read (tamper hardening).
- **SyncTime**: `{mtime: SystemTime, sha256}`; mtime serialized `"<secs>;<nanos>"`; sha256 = hex of content at last sync.
- Paths: config `$XDG_CONFIG_HOME/dfm/config.toml` (fallback `~/.dfm.toml`); state `$XDG_STATE_HOME/dfm/state.toml`; target ignore `$XDG_STATE_HOME/dfm/ignore_file`; source ignore `<source>/.dfm_ignore_file`; source marker `<source>/.dfm_root` (content `.`). Non-UTF-8 paths via `to_string_lossy()`, never `to_str().unwrap()`.
- main.rs needs the state file for add/pull/forget/merge/diff/status (`NotFound` otherwise); init/config/purge/ignore/paths work without it. Missing config file → silent defaults (`NotFound`, no warning); corrupt/unreadable config → warning.

## Path encoding (lib.rs)

- target→source: leading `.` of a component → `dot_prefix` (`dot_bashrc`↔`.bashrc`); `add_postfix_opt` appends `.symlink`/`.encrypted` **to the full filename** (`link-to-file.txt.symlink`). Encoding is injective: literal `dot_` → `~dot_…`, literal `~` → `~~…`. `source_rel_to_target_rel` inverts component-wise.
- `file_path_relative_to(abs,dir)` → rel; `remove_dots_from_path` resolves `.`/`..` lexically.

## Ignore matching (lib.rs)

One regex per line; `#` comment (`\#` escapes); blank skipped → `RegexSet`. **Root-anchored component matching** for all ignore checks: pattern split on `/`, each sub-pattern anchored `^(?:…)$` unless it has own `^`/`$`; path split on `/`, leading `.` dropped. Single sub-pattern **with** a left-glob (`.*`/`^`) tests every component at any depth; **without** it matches only the **first** component (`abc` → `abc/…`, never `dir/abc/…`). Multi-part patterns match first components in order (no sliding): `dir/abc` hits `dir/abc/…`, not `x/dir/abc/…`. `dirname/` ≡ `dirname`. `dfm ignore PATH` stores `regex::escape` of the **lexical target-relative** path (symlink records itself, not pointee) → anchored at target root by construction; a **source-side** path goes to the *source* ignore as `^<target-rel>$` stripped of `dot_`. `force_encryption_for` uses full-path substring matching instead. Dir-subtree probe = `R + "/x"` sentinel.

## Conflict detection (lib.rs) — `compare_files(encrypted_postfix, TF, SF, sync)`

```
both_not_modified    = TF==sync && sync==SF
only_source_modified = (TF==sync && sync<SF) || TF<SF
only_target_modified = (TF>sync && sync==SF) || TF>SF
both_modified        = TF>sync && sync<SF   → also NeverSynchronized (no entry)
```

Fallback `TF<SF`/`TF>SF` covers mtime granularity. Encrypted sources compare by **timestamps** (re-encryption changes bytes); plain sources by sha256 vs stored hash. `sync` = stored `SystemTime`.

## Shared helpers (commands/mod.rs)

- `sync_file_copy` (copy + preserve perms + set mtimes + update state); `update_sync_state` (sha256 + `SyncTime{now}`); `get_sync_time`/`remove_sync_state`.
- `resolve_source_variant` → `SourceVariant{Plain,Encrypted,Symlink}` (plain→encrypted→symlink order).
- `source_rel_to_target_rel` / `source_rel_to_target_abs` (shared source→target mapping: pull, merge, status, purge).
- `cli_path_to_abs(path)` — user PATH arg: absolute → `remove_dots`; relative → join **CWD** (shell semantics) + lexical normalization. `cli_path_in_scope(arg, target, source)` — that + check start_with target OR source else `InvalidInput`; wired into status/add/pull/merge/forget/ignore at argument entry. **diff stays permissive** ("not managed").
- `resolve_dry_run`, `require_force`, `prune_ignore_file`, `prune_matched_ignore_patterns` (after successful add/pull `--force`, drop matched patterns), `is_ignored` (bool ignore check, never prunes — used by sync), `read_symlink_pointer`, `split_command` (whitespace-split template → program+args).
- `resolve_tool_command(cmd_opt, tool_name, config_key)` → tool command or `Other("no {tool} tool configured — set {key} in config")`.
- `run_merge`/`run_diff`: `.current_merge`/`.current_diff` scratch dirs in the source dir resolved from `source_dir_abs_path`, created mode **0700** (`create_private_temp_dir`), stale leftover removed up front, `DirGuard` cleans up on Drop. Tool is spawned **directly, no shell** (`|`,`>` don't work); missing program → `NotFound("… tool {prog} not found")`. diff creates the scratch dir only for **encrypted** sources (plain diffs pass `{source}` straight through → works on read-only source dirs).
- `report_progress`/`ProgressLine`: single `\r`-overwriting stderr line; shown at `-v 0/1`, suppressed at `-v ≥ 2`; silent below 100 files (~20 updates).

## Command semantics (key contracts)

- **init**: create source, `.dfm_root` chain, extend source ignore (`.dfm_root`,`.git`, `.dfm_ignore_source`,`.dfm_ignore_target`,`.current_merge`,`.current_diff`), state file + default config. Never looks for config inside source.
- **add**: skip dfm runtime files (state, target-ignore) and out-of-target paths. The **config file is NOT skipped** — it is a manageable dotfile (named or traversed). Symlink → pointer file (no pointee fallthrough). Ignored → skip unless `--force` (`handle_ignore_or_override` also prunes the matching pattern, for symlinks too). Conflicts need `--force`; `conflict_detected` only for explicitly-named paths. `-s`/`-e` mutual exclusion; `-e` on symlink = error; encrypted add deletes stale plain source+state. `CopyAndSymlink` renames target to `.dfm-backup` sibling, creates symlink, drops backup only on success (restores on failure).
- **pull**: reverse mapping; missing target → per type `CreateOrUpdateSymlink`/`Decrypt`/`Copy` (symlink with `-s`); encrypted uses `handle_encrypted_timestamps` (Both/Target/NS → `--force`, Source → decrypt).
- **sync**: filesystem-walk targets; only files with a source **and** a sync record are eligible (unmanaged/never-synced/unpulled skipped). NonModified→skip; SourceModified→pull; TargetModified→add; BothModified→conflict. Without `--force`: traverses all eligible files and exits non-zero when conflicts exist (nothing modified). With `--force`: conflicts not treated as errors, eligible files copied, never touches conflicts, exit success. Ignored files never processed (with or without `--force`; the `is_ignored` helper, no pattern pruning — sync never edits the ignore file). `--symlink`/`--encrypt` removed from sync (no conversions). Uses shared helpers (`list_directory` PruneIgnoredDirs, `resolve_source_variant`, `get_sync_time`, `compare_files`, `update_sync_state`). Traversal symlinks handled by `handle_symlink`/`UpdatePointer` (pointer-file layout only); encrypted pairs sync via `AddEncrypted`/`PullEncrypted`.
- **merge**: no paths → only `BothModified`; paths → any modified. `merge_tool_command` success = exit 0 AND result exists; copy result to both sides (re-encrypt if needed), `update_sync_state`, clean up.
- **diff**: read-only, never touches state/target, exit 0 with no args. Situations: missing source → `is not pulled`; no source → `is not managed`; exists nowhere → `does not exist`; `is ignored by <re>`. Decrypted content offered **as a file only**, never stdin (vim reads stdin into `[No Name]`; `:qa` fails E37/E162).
- **forget**: never deletes targets. No paths → all (traverse target + orphan state keys). Explicit path resolving to nothing → `NotFound("<path> does not exist")`, before any task, exit 1, `--force` doesn't suppress. 3 phases: best-effort delete sources → remove state → prune empty parents. Dispatched via `with_state_even_if_error` (state entry removed before source deletion runs, so it must persist even on failure).
- **ignore**: `-p` raw, `-r` remove from target ignore, mutually exclusive (ArgGroup → no args is a CLI error). Appends with trailing-newline guard.
- **purge**: abort (unless `-f`) on un-pulled source changes. Removes config (unless `-c`), source (unless `-s`), state dir. **Config parent dir removed only when config is the default one** (never `$HOME`); custom `-c PATH` removes just the file.
- **config**: `--get|--set|--list`; note `dfm config list` positional is NOT valid syntax.
- **status**: Phase 1 `state.syncs` → codes (each entry checked against BOTH ignore files; source-ignored → `!!`, never `!?`); Phase 2 walk target for unmanaged/ignored (skips state + target-ignore + source-dir contents); Phase 3 stale-pattern detection is **full-tree only**. Codes: `--` ok, `MM` both modified, `M ` target, ` M` source, `NM` never-synced, `!?` unpulled, `??` unmanaged, `?L` unmanaged symlink, `LL` managed symlink, `!!` ignored, `!L` ignored symlink, `!P` stale pattern. Default view: git header (`git -C <source> status --porcelain -b`), dirs collapsed `dir/*`, paged (`$PAGER`/`less -FRSX`, `stty size`) only when output > terminal height **and** stdout is a terminal (`IsTerminal`). Path scoping: absolute or target-dir-relative (or source → mapped back); scoped reports skip the stale block; `--short`/`--porcelain` uncolored/unpaged; filters `-a -c -m -U -M -p -e -i -l -u`. Each `StatusEntry` carries `encrypted` (= Phase-1 source_rel ends with `encrypted_postfix`; Phase-2 symlink/unmanaged/ignored entries are never encrypted). In the default report encrypted entries render with a right-aligned `(encrypted)` marker in the annotation column (same column shared with `(pattern)`; both can appear together); a wholly-encrypted folded dir prints as `dir/* (encrypted)`, a mixed dir folds without the marker and its encrypted members show individually under `-e`. `--short`/`--porcelain` never show the marker. `-e/--encrypted` overrides all other restrictive filters: it keeps only `encrypted` entry in whatever category and suppresses the stale block; it does NOT unhide UpToDate/Unpulled blocks beyond the normal rules (`show_unpulled` = `unpulled || all`), so pure `-e` keeps Unpulled hidden in the default report. `--porcelain`/`--short` unchanged. The **Unpulled block is excluded from the default (no-flag) report** — only `--unpulled` (`-p`) or `--all` show it; `--short`/`--porcelain` still list `!?` in default mode (gated in `format_default` via `show_unpulled` = `unpulled || all`, so filtered `!?` also drops out of Unpulled folding for sibling groups).

## Encryption (crypt.rs)

Self-contained **DFMENC** blob (`FORMAT_VERSION = 2`). Public header: Argon2id `(m_cost KiB, t_cost, p_cost)`, 16B salt, 24B nonce, chunk_size u32, plaintext_len u64. Key: Argon2id (release 64MiB/t3/p4; debug 8MiB/t1/p1). Payload = chunked XChaCha20-Poly1305 records (ct ≤ 64 KiB + 16B tag); per-chunk nonce = base nonce with last 8B := 7B BE counter + final-flag byte; per-chunk AAD = header||idx||flag → reorder/dup/truncate/splice all fail auth. **Streaming: peak RAM O(chunk)** regardless of file size. Metadata carries inner name, file mode, and a non-encrypted entry per enclosing dir (restores e.g. a 0700 `.ssh` on pull). `decrypt` caps read KDF params (`m_cost ≤ 16GiB`, `t_cost ≤ 10`, `p_cost ≤ 1024`). Wrong password: first-chunk auth failure only (retried once after clearing cache); later failures = "corrupted", partial target removed. Encrypt writes `<dest>.part` + rename. `obtain_password`: configured `obtain_password_shell_command` piped to `sh` **stdin** (not `-c`, invisible in `ps`) else masked rpassword prompt; password cache is process-global `Mutex<Option<String>>`. All notices → stderr.

## Traversal (list_directory)

`WalkDir::filter_entry`; `follow_links(false)` + `follow_root_links(false)`. `TraversalFilter::KeepMatching` (pull: keeps rel-path matches, skips dot files AND dot dirs) or `PruneIgnoredDirs` (add/forget/status/ignore: keep all files, prune fully-ignored dir subtrees via `R + "/x"` sentinel). Root always kept so a named ignored path is entered; pruned dirs recorded and rendered as one `!! dir/` (status). `NotFound` passes path through; directories skipped.

## Conventions

- **Task pattern**: analysis queues task enums; execution loop runs them; `continue` in analysis never cancels already-queued tasks.
- **State dispatch**: `add`/`pull`/`merge` → `with_state` (state written only on success); `forget` → `with_state_even_if_error`; `status` → read-only borrow.
- **`main_logic`** resolves state/config as `Option`: unresolvable paths warn and continue (purge/paths work with `$HOME` unset); mutating commands then error via `with_state`.
- **No shell** for `merge_tool_command`/`diff_tool_command` (whitespace-split, direct spawn).
- **Unreadable objects** (`PermissionDenied`: strict perms, wrong owner) are **skip-with-warning**, never a command failure — in `list_directory`, per-file analysis, and task execution loops (except `NotFound`, which passes roots through; other errors fail the command).
- **Root guard** (lib.rs, first thing in `main_logic` after Args::parse): `check_root_privileges()` reads real+effective uid via hand-rolled externs `#[link(name="c")] unsafe extern { getuid, geteuid }` (edition 2024 needs `unsafe extern`; symbols from already-linked libc, no new dep). Refuse iff `euid==0 && (ruid!=0 || SUDO_USER non-empty)` — genuine root (0,0,None) allowed; `euid!=0` never refused. Error `InvalidInput` naming sudo vs setuid-style elevation, exit 1; `--help`/`--version` still work (clap exits first). Unit: `test_refuse_root_access_matrix`. No shell integration test (user removed it). Shell test counts are 217, Rust unit 30.
- Build notes: installed `/usr/bin/dfm` is an older build **without** the root guard; detect euid-0 with `unshare -r` (emulates euid 0 without privileges), never with sudo.

## Testing conventions (launcher.sh)

- Every test: subshell `set -eEu -x`, fresh temp `$HOME`, sandbox exports HOME + all four XDG vars (must `mkdir -p`), prefers debug binary. Tests must never read stdin.
- Helpers: `dfm()`, `write <content> <path>` (2 args, mkdir -p parent), `assert <expr...>`, `assert_succ <cmd>`, `assert_fail` (fails if command exits 0), `run_fail <cmd...>` (asserts non-zero exit, captures combined output into `$FAIL_OUTPUT`), `assert_source <rel>` / `assert_no_source`, `assert_content_eq`, `add_file <name> [content]`, `assert_encrypted` (needs `$PASSWORD`), `uuid` stub.
- **Assertion rule (grep over captured output, `set -eEu` gotchas)**: positive → plain pipeline (`dfm status 2>/dev/null | grep -qF "pat"`). Negative → **never** `! cmd | grep -qF` (POSIX `-e` skips `!`-inverted commands → false-pass); capture first then let grep be the only command: `RES=$(...); assert_fail grep -qF "pat" <<<"$RES"`. Expected failures → `run_fail dfm ...` then `assert_succ grep -qF "msg" <<<"$FAIL_OUTPUT"`. Under `set -e`, `RES=$(… dfm …)` inherits a non-zero rc → guard `|| true`. Files starting with `-`/`+` need `grep -qF -- "-$VAR"`. Avoid `dfm | grep` pipes where possible; redirect stderr to a file to check it.

## Manual testing (without launcher.sh) — caveats

- **Sandbox everything**: `export HOME; export XDG_CONFIG_HOME XDG_DATA_HOME XDG_CACHE_HOME XDG_STATE_HOME` to fresh temp dirs and `mkdir -p` them; run the **debug build** (`target/debug/dfm`). Never run dfm against the real `$HOME` (it can damage user files — add/pull/forget act on whole trees). Do not install the built distributive.
- Set the rustup toolchain PATH before building (see Build/test); `cargo build` first.
- `unshare -r` gives euid 0 to a non-root user → verifies the root guard (fake `SUDO_USER=alice` refused, `DFM_ALLOW_ROOT=1` bypasses, genuine root runs). `sudo` runs `/usr/bin/dfm` (stale binary) — not the build you just made.
- `dfm config list` is invalid syntax (needs `--get/--set/--list`); `config get` on a missing key warns, exit 0.
- dfm should never read stdin in scripts: avoid interactive password prompts by clearing stdin (`< /dev/null`) or rely on `$PASSWORD` only if plainly intended.
- Status paging (and future `diff --all`) only spawns `$PAGER` when stdout is a terminal — a pipe/file never triggers it, so piping is safe.
- `run_fail` env assignments must use `env K=V "$BIN"` form (positional `"$@"` are not env assignments) — test harness concern.

## Debug strategies (in order)

1. Run the failing test alone: `bash tests/launcher.sh test_x.sh` (full `-x` trace). Read the failing assertion + lines above before touching code.
2. If trace shows success but wrong output, add **one** `eprintln!` at the point the asserted value is computed, print actual, compare to expectation.
3. Read the function end-to-end to form a hypothesis, confirm with 2.

| Symptom | Likely cause |
|---|---|
| `grep` 1 on `dfm status` | entry in hidden category (`LL`/`--`/`!!`/`!L`) — try `--all`/`--short` |
| `test -f` fails for pointer file | `.symlink` postfix appended to full filename |
| `assert_source` fails | dot-prefix/postfix/path-component mismatch in computed source path |
| queued task still runs after `continue` | tasks already queued execute in the final task loop |

## Roadmap

`ROADMAP.md` (Implement features + Documents) is the current feature plan. Every task has been through ambiguity-elimination Q&A and is rewritten precisely there; the "Information to add to the tasks" appendix says **RESOLVED** for all items. Key decisions in short:
- `status --encrypted` (`-e`) overrides other filters; filters combine additively (no contradictory-flag error); `(encrypted)` marker in human output only (right-aligned; `dir/* (encrypted)` when whole group).
- Auto-encrypt when any component (target-root down) has `mode & 0077 == 0`; unions with `force_encryption_for`; newly added files only; symmetric on pull.
- `diff --editable` (`-e`): require equal target/source content first; write back both sides + update sync **only on tool exit 0**; re-encrypt encrypted side.
- `sync`: only synced+modified files; BothModified = conflict (no `--force`: prints paths, nothing modified, exit ≠ 0; with `--force`: skips conflicts); plan-all/commit-once.
- `diff --all` (`-a`, default true via config `diff_all_default`; template `diff_all_tool_command` default `diff -u --color=always {source} {target}` / reversed for SourceModified) — line executed as one argument to `sh -c '…'`, placeholders verbatim; BothModified diffed, never-synced silent; encrypted decrypted to scratch.
- Action-phase progress bar (add/pull/sync): 1 step/file, stdout, TTY-only, on by default.
- `status <path>` with exactly one path and nothing to report → `<path> is up-to-date.` (stdout).
- Documents: GPL-3.0-only in a separate LICENSE file (not embedded); README states pure-local sync; shrink README/context.txt by pre-agreed per-section line budgets.
- Considerations ("source file owned by another user"): user marked **not ready** — open question, must become a decision before it can be a task.
