# DFM — Dotfile Manager (Rust)

Rust CLI that syncs dotfiles between a **target** dir (usually `$HOME`) and a
**source** dir (a git repo like `~/dotfiles`).

Commands: `init`, `add` (target→source), `pull` (source→target), `merge`,
`diff`, `forget`, `purge`, `ignore`, `paths`, `config`, `status`,
`encrypt`, `decrypt`.

Global flags: `-n/--dry-run`, `-v <0-3>`, `-c <PATH>` (alt config). Verbosity:
`-v 1` brief (default), `-v 2` info, `-v 3` debug.

## Build / test

```bash
cargo build                            # debug
cargo build --release                  # panic=abort, opt-level z, lto fat
cargo test                             # 30 unit tests (lib.rs + crypt.rs)
bash tests/launcher.sh -q              # 209 shell integration tests
bash tests/launcher.sh tests/test_x.sh # run one test (shows -x trace)
cargo aur                              # target/cargo-aur tarball + PKGBUILD
```

Build.rs renders `dfm.1` (via clap_mangen) into target/<profile>/dfm.1 on every
build; `cargo aur`'s release build puts it at target/release/dfm.1, which
`[package.metadata.aur] files` packs and installs to /usr/share/man/man1/dfm.1.

```

                     Args/Command from dfm::cli

src/commands/{add,pull,merge,diff,forget,init,ignore,purge,config,paths,status,encrypt}.rs

tests/test_*.sh      209 shell tests
```

## Key types (lib.rs)

- **`DfmError`** — `Io`, `Unsupported`, `NotFound`, `InvalidData`,
  `InvalidInput`, `Other`; `From<io/toml::ser/toml::de/regex/microxdg::XdgError>`.
  Shorthand `DfmError::other(msg)`.
- **`Settings`** — merged runtime config: `source_dir`, `target_dir`,
  `dot_prefix` ("dot_"), `symlink_postfix` (".symlink"), `encrypted_postfix`
  (".encrypted"), `force_encryption_for` (default `\.ssh`),
  `obtain_password_shell_command`, `merge_tool_command` (default
  `vimdiff {target} {source} {result}`), `diff_tool_command` (default
  `vimdiff -M {target} {source}` — read-only). `force_encryption_for` is checked
  against `BY_DEFAULT_FORCE_ENCRYPTION_FILES` (`std::sync::LazyLock<Vec<Regex>>`,
  default `\.ssh`).
- **`Config`** — same fields, optional, TOML. **source_dir/target_dir are NOT
  in config** — they come from the state file.
- **`StateObject`** — `{ source_directory, target_directory, syncs:
  HashMap<String, SyncTime> }`. State file `$XDG_STATE_HOME/dfm/state.toml`.
  Sync key = source-relative path (validated on read via
  `validate_state_key`: rejects `..`/absolute/drive components — tamper
  hardening). `read_state` returns an error on any invalid key.
- **`SyncTime`** — `{ mtime: SystemTime, sha256: String }`. `mtime` serializes
  via `sync_time_ser` as `"<secs>;<nanos>"`; `sha256` = hex SHA-256 of the
  content at last sync. Content hashing makes change detection deterministic
  (independent of filesystem mtime granularity). `Deref<Target=SystemTime>`.
- **Conflict detection (lib.rs)**: `compare_files(encrypted_postfix, TF, SF, sync)`
  dispatches on source type — `.encrypted` → `compare_files_by_timestamps`
  (mtime, since re-encryption changes bytes); plain → `compare_files_by_content`
  (sha256 vs stored hash). See **Conflict detection** below for the algorithm.

## Paths (lib.rs)

- Config `$XDG_CONFIG_HOME/dfm/config.toml`, fallback `~/.dfm.toml`
  (`calc_config_file_path`). State `$XDG_STATE_HOME/dfm/state.toml`; target
  ignore `$XDG_STATE_HOME/dfm/ignore_file`; source ignore
  `<source>/.dfm_ignore_file`; marker `<source>/.dfm_root` (content `.`).
- Paths are built with `Path::join`/`PathBuf::push`; XDG subdirectory paths are
  assembled with `format!("{}/{}", dir, name)` and passed to the `xdg` helpers.
  Non-UTF-8 paths are handled via `.to_string_lossy()`/`.display()` where a
  `String` is required — no `to_str().unwrap()` panics.
- `filepath_in_source_dir` target→source: leading `.` in a filename/component
  becomes `dot_prefix` (`dot_bashrc`↔`.bashrc`, `dot_config/foo`↔`.config/foo`);
  `add_postfix_opt` appends `.symlink`/`.encrypted`. The encoding is injective:
  a literal `dot_`-prefixed component is escaped as `~dot_…` (a literal `~` as
  `~~…`). `source_rel_to_target_rel` inverts this component-wise (state key →
  target-rel: unescape `~`, `dot_`→`.`, strip postfixes).
- `file_path_relative_to(abs, dir)` → rel; `remove_dots_from_path` resolves
  `.`/`..` lexically (returns `.` when empty, keeps root `/`).

## Ignore matching (lib.rs)

One regex per line; `#` comments (`\#` escapes); blank lines skipped
(`load_ignore_regex` → `RegexSet`). **Root-anchored component matching**
(`check_path_matches_regex_component_wise` / `pattern_matches_path_components`)
is used for all ignore checks. Pattern split on `/`, empty segments dropped
(each side); each sub-pattern anchored `^(?:…)$` unless it has its own
`^`/`$`; path split on `/`, leading `.` component skipped. Single sub-pattern
with a left-glob (`.*`/`^`) tests every component at any depth; **without** a
left-glob it matches only the **first** path component (`abc` ignores
`abc/…`, never `dir/abc/…`). Multi-part patterns match the first components
in order (root-anchored sequence, no sliding): `dir/abc` matches `dir/abc/…`
but not `x/dir/abc/…`. Records stored by `dfm ignore PATH` are the escaped
target-relative paths, so they anchor at the target root by construction.
Trailing-empty segments are dropped → `dirname/` ≡ `dirname`.
`check_path_matches_regex_substring` (full-path substring) is used only for
`force_encryption_for`. `dir_ignore_pattern`/`is_dir_ignored` probe a dir as
`R + "/x"` (sentinel) to test whether its subtree is fully ignored.

## Conflict detection (lib.rs)

`compare_files` returns `BothModified | SourceModified | NonModified |
TargetModified | NeverSynchronized`, evaluated in order (`sync` =
`sync_time_opt` SystemTime):

```
both_not_modified    = TF==sync && sync==SF
only_source_modified = (TF==sync && sync<SF) || TF<SF
only_target_modified = (TF>sync && sync==SF) || TF>SF
both_modified        = TF>sync && sync<SF
```

Fallback clauses `TF<SF`/`TF>SF` cover mtime granularity; else error
"timestamps ... inconsistent". No `NeverSynchronized` → no sync entry.

## Shared helpers (commands/mod.rs)

- `sync_file_copy(from, to, source_file_in_source_dir, state, source_dir)` —
  copy, preserve permissions, set mtime on both sides, update state.
- `update_sync_state` — compute `sha256(source)`, insert `SyncTime{now,
  sha256}`, set mtime on both sides (via `filetime_creation`).
- `get_sync_time` / `remove_sync_state` — look up / drop a state entry by
  source-relative path.
- `resolve_source_variant(settings, ...)` + `SourceVariant{Plain,Encrypted,
  Symlink}` — resolve an existing source for a target path, tried in order
  plain → encrypted → symlink pointer; `None` when the target has no source.
- `source_rel_to_target_rel(state_key, ...)` — state key → target-rel: strip
  `dot_prefix`→`.`, drop one trailing symlink/encrypted postfix.
- `source_rel_to_target_abs(source_rel, target_dir_abs, settings) →
  (target_rel, target_abs)` — shared source−-rel→target mapping (join + remove
  dots) used by pull, merge, status, purge.
- `cli_path_to_abs(path) -> Result<PathBuf>` — resolve a user PATH argument:
  absolute → `remove_dots_from_path`, relative → join the **current working
  directory** (normal shell semantics), then lexical normalization. Used by
  diff + add's symlink branch + forget's lexical fallback; `init` resolves
  its own arguments.
- `cli_path_in_scope(arg, target_dir_abs, source_dir_abs) -> Result<PathBuf>`
  — `cli_path_to_abs` + scope check: resolved path must start with target OR
  source dir, else `InvalidInput("path … resolves to …, which is outside the
  target directory …")`. Used by status (`resolve_status_paths`),
  add, pull, merge, forget, ignore at their argument entry. Rationale: an
  escaping path (leading `..` past the managed root, or absolute elsewhere)
  used to silently escape the tree — status printed mangled `?? ./../../<abs>`
  entries via `file_path_relative_to`'s fallback; add gave raw I/O errors;
  diff said "not managed". diff stays permissive on purpose.
- `resolve_dry_run(cmd_flag, global_flag)`; `require_force(force, msg)`;
  `prune_ignore_file(path, should_ignore, dry_run)` (keeps blank lines + full
  kept-line text, returns removed, writes only when something removed and
  not dry-run); `prune_matched_ignore_patterns(xdg, patterns, dry_run)` (after
  successful add/pull `--force`, drop the matched target-ignore patterns);
  `list_directory_or_error`; `msg_dry_run()`/`msg_nothing_to_do()`;
  `read_symlink_pointer`/`symlink_pointer_matches`.
- `split_command(cmd) -> (Option<&str>, Vec<&str>)` — whitespace-split a command
  template into program + args; shared by `run_merge` (merge tool),
  `run_diff` (diff tool), and `print_paged` (pager).
- `resolve_tool_command(command_opt: &Option<String>, tool_name, config_key) ->
  Result<String, DfmError>` (mod.rs) — returns the configured tool command, or
  errors with `Other("no {tool_name} tool configured — set {config_key} in
  config")` when unset/empty; used by `run_merge`/`run_diff` (config key
  `merge_tool_command`/`diff_tool_command`).
- `DirGuard` (mod.rs, `pub(crate)`) — removes a `.current_merge`/`.current_diff`
  dir on Drop; `run_merge` and `run_diff` remove a stale leftover up front.
- `create_private_temp_dir(path)` (mod.rs) — recursive mkdir with mode 0700
  (`DirBuilderExt::mode`), so decrypted scratch files in `.current_merge`/
  `.current_diff` are not world-readable while a tool runs; used by both
  `run_merge` and `run_diff`.
- `report_progress` + `ProgressLine` — single self-overwriting stderr line
  (`\r` + pad); shown at `-v 0/1`, suppressed at `-v ≥ 2` (single gate in
  `ProgressLine::set`, no-op when `log::max_level() >= Info`). `report_progress`
  throttles to ~20 updates and is silent below 100 files.

## Commands (semantics)

- **`init <SOURCE> [TARGET]`** — create source dir; follow/create `.dfm_root`
  pointer chain (content `.`); extend source ignore with `.dfm_root`, `.git`,
  `.dfm_ignore_source`, `.dfm_ignore_target`, `.current_merge`, `.current_diff`
  (the merge/diff temp dirs); create state file + default config. Does **NOT**
  look for config inside the source dir (README matches).
- **`add [PATH...] [-f] [-s] [-e]`** — traverse target (or given paths). Skips
  dfm runtime files (state file, target ignore) and out-of-target paths,
  source-dir paths. The dfm config file is NOT skipped: it is managed like any
  other dotfile (named or traversed; `dfm add .config/dfm` works). Symlink →
  pointer-file (`CreateSymlinkFilePointer`, no pointee fallthrough). Ignored →
  skip unless `--force`; `--force` **also overrides for ignored symlinks**
  (both use `handle_ignore_or_override`, which removes the matching
  target-ignore pattern). Conflicts
  (`SourceModified`/`BothModified`/`NeverSynchronized`(≠content))
  need `--force`; `conflict_detected` set only for explicitly-named paths
  (silent skip during traversal). Tasks: `Copy`, `CopyEncryptedFile`,
  `CreateSymlinkFilePointer`, `CopyAndSymlink` (copy→source, rename target to a
  `.dfm-backup` sibling, symlink target→source relative, drop backup; on
  symlink failure the backup is restored over the target), `UpdateSync`. `-s`
  and `-e` mutually exclusive; `-e` on a symlink is an error; encrypted add
  deletes stale plain source+state.
- **`pull [PATH...] [-f] [-s]`** — traverse source (dotfiles pruned via
  `^(.+/)?[^.][^/]+$`) or given paths (source→infer target, target→compute
  source). Missing target: symlink-file→`CreateOrUpdateSymlink`; `.encrypted`→
  `Decrypt`; else `Copy` (symlink with `-s`). Existing target symlink recreated
  if pointee differs. Encrypted: `handle_encrypted_timestamps`
  (BothModified/TargetModified/NeverSynchronized→`--force`, SourceModified→
  decrypt). Tasks: `Copy`, `CreateOrUpdateSymlink`, `Decrypt`. Decrypt sync
  key = encrypted source path.
- **`merge [PATH...] [-n]`** — no paths: merge only `BothModified` state
  entries. With paths: merge any modified file; resolve source/target path,
  try state keys exact/`.encrypted`/`.symlink` (`resolve_state_key`); skip
  symlink targets + ignored.   Calls `run_merge` (mod.rs): `.current_merge/` in
  source dir (**resolved from `source_dir_abs_path`, and a stale leftover
  `.current_merge` is removed first**, created with mode 0700), copy `target.<f>`/`source.<f>` (decrypted if encrypted), result
  `<f>` is **not pre-created**; `merge_tool_command` = first whitespace token =
  program, rest = args with `{target}`/`{source}`/`{result}` replaced, run
  directly (no shell). Success = exit 0 **and** result exists; copy result to
  both sides (re-encrypt if needed), `update_sync_state`, clean up. Program
  missing → `NotFound("merge tool {prog} not found")`.
- **`diff [PATH...]`** — read-only; no paths → do nothing, exit 0 (also does
  nothing when the state file is missing, like no paths). `diff_one_path`
  resolves source-side (target-rel via `starts_with(source_dir_abs_path)` +
  `state_key_for`) or target-side (via `file_path_relative_to`, `!starts_with(
  target_dir_abs_path)` → not managed); `path_exists` (via `symlink_metadata`,
  `NotFound` only) distinguishes a missing path from permission-denied.
   Situations: target symlink → print both pointees; source missing → `<path> is
   not pulled` (computed target abs path); no source (existing target, or
   missing source path whose inferred target exists) → `<path> is not managed`;
   exists nowhere — given path and counterpart both absent, both branches →
   `<path> does not exist`;
  ignored (target ignore file only) → `<path> is ignored by <regexp>`; unreadable
  → `skipping unreadable path ...`; `get_sync_time`/`compare_files` → NonModified
  → `<path> is synchronized`, else encrypted content-compare
  (`read_encrypted_bytes` vs `fs::read(target)`) or sha256 compare → differ →
  `run_diff` (mod.rs): `DirGuard`; the `.current_diff/` scratch dir (created
  with mode 0700 when needed) is only touched for **encrypted** sources — plain
  diffs pass `{source}` straight through and never write into the source dir
  (read-only dirs work), substitutes `{target}`/`{source}` via `split_command`,
  run directly (no
  shell). Decrypted content is offered **as a file only**, never via stdin —
  vim reads a piped stdin into a `[No Name]` buffer and `:qa` then fails with
  E37/E162. Program missing → `NotFound("diff tool {prog} not found")` (exit
  1); tool's non-zero exit → `debug!` only. Never writes state (immutable
  borrow) nor touches the target.
- **`forget [PATH...] [-f]`** — never deletes targets. No paths → all
  (traverse target + orphan state keys; orphan source checked modified → needs
  `--force`). Dispatches per path: `handle_target_symlink` (returns bool: fully
  handled vs falls through to pointee), `handle_missing_target` (returns bool:
  resolved to nothing), `handle_source_path`, `handle_target_file`. An
  explicitly-named path resolving to nothing — canonicalize NotFound, no source
  variant, and for a lexically-source-side path the inferred target absent too
  (`source_rel_to_target_rel`) — is collected into `missing_paths` and fails
  after analysis with `NotFound("<path> does not exist")` (plural form for
  several), before any task runs: nothing is forgotten, exit 1, `--force` does
  not suppress it; broken symlinks keep silent handling. Tasks:
  `Delete(source)`,
  `RemoveState(key)`, 3 phases: (1) best-effort delete sources (NotFound ok,
  other errors collected → fail), (2) remove state, (3) prune empty parents.
  `--force` when source modified or symlink pointer mismatches (`SourceModified`
  /`TargetModified`/`BothModified` all gate on `--force`). Symlink pointing into
  source dir also deletes the target symlink. Note: main.rs dispatches `forget`
  through `with_state_even_if_error` (persist state even when the command fails),
  because the state entry is cleaned up before source deletion runs.
- **`ignore [PATH...] [-p PAT...] [-r REC...]`** — writes `regex::escape(rel)`
  (lexical target-relative form, symlink NOT resolved so a link records
  itself) of target paths to the target ignore, but a **source-side** path is
  stored in stored in
  the *source* ignore as its target-rel form: `^...$` with `dot_prefix` stripped
  (source `dot_my.log` → target `.my.log` → `^my\.log$`); already-ignored
  source entries are migrated (`migrate_ignore_line`). `-p` raw patterns
  (validated); `-r` removes records from the *target* ignore (raw or escaped
  match). `paths`/`patterns`/`remove` are mutually exclusive (clap ArgGroup
  required → no args is a CLI error, despite README). Appends with
  trailing-newline guard (`ensure_trailing_newline`).
- **`purge [-s] [-c] [-f]`** — abort (unless `-f`) on un-pulled source changes
  (mtime > sync). Removes config (unless `-c`), source dir (unless `-s`), state
  dir. Each component resolved independently; unresolvable → skipped with info
  log (works with `$HOME` unset). Removal I/O errors aggregated at the end.
  The config file's **parent directory** is removed only when the config file
  is the default one (matches `calc_config_file_path`, and never `$HOME`); a
  custom `-c PATH` removes just the file — a sibling file next to a custom
  config survives a purge.
- **`config --get|--set|--list`** — TOML properties; `--set` stores strings;
  array fields not settable.
- **`encrypt <FILE> [-o]` / `decrypt <FILE.encrypted> [-o]`** — standalone
  (crypt.rs) DFMENC blob operations, outside the target/source workflow;
  `decrypt` restores recorded perms. Both go through `obtain_password`.
- **`paths`** — prints Source/Target/Config/State/Local ignore/Source ignore;
  `unresolved` for Config/State/Local ignore when the XDG path cannot be
  resolved (no panic with `$HOME` unset).
- **`status [PATH...] [--short|--porcelain] [filters]`** — Phase 1
  `state.syncs` → codes; each entry is checked against BOTH ignore files:
  target-side (`!!`/`!L`) and source-side `.dfm_ignore_file` (also `!!`/`!L`)
  so a source-ignored entry is never offered as pullable — removing its
  target copy yields `!!`, not `!?`; Phase 2 walk target for unmanaged/ignored
  files (skips
  dfm runtime files: state, target-ignore, and anything inside the
  source dir; the dfm config file is reported like any dotfile — `??` when
  unmanaged, state-driven codes when managed;
  `classify_target_symlink`/`classify_target_file`); fully-ignored
  pruned dirs → one `!! dir/`. **Path scoping** (`resolve_status_paths`): each
  PATH absolute/relative to the target dir, or a source-dir path mapped back to
  its target counterpart (like `pull`); nonexistent → error; no PATHS → whole
  target. Phase 1 keeps `state_keys` full (drives classification) but emits only
  in-scope entries; Phase 2 walks only the requested roots (folding matches the
  full report). Phase 3 stale/unused-pattern detection is **full-tree only**:
  scoped reports skip the whole block (a pattern used outside the scope would
  falsely read as unused); `--unused-patterns` re-walks the full target even
  with PATHS. Codes: `--` ok, `MM` both modified, `M ` target, ` M` source,
  `NM` never-synced, `!?` unpulled, `??` unmanaged, `?L` unmanaged symlink,
  `LL` managed symlink, `!!` ignored, `!L` ignored symlink, `!P` stale pattern.
  Entries are **sorted by path** before output so every mode (porcelain/short/
  default) is deterministic despite Phase 1 iterating a HashMap.
  `LL` shown only when the symlink's *pointee* resolves into source dir **and**
  is in state (or pointer file in state). Default view (grouped into "Changes
  to merge/add/pull", "Unpulled", "Unmanaged files", "Up to date", "Ignored",
  "Unused ignore patterns"): colored paths, dirs collapsed to `dir/*`
  (`collapse_shared_dirs`), git header via `git -C <source> status --porcelain
  -b` (`get_git_info`: branch + ahead/behind + dirty/clean), paged
  (`$PAGER`/`less -FRSX`, via `stty size`) only when output exceeds terminal
  height **and stdout is a terminal** (`IsTerminal` — a pipe/file is never
  paged). `--short` = `<code> <path>`; `--porcelain` = tab-separated, both
  uncolored & never paged. Filters: `-a -c -m -U -M -p -i -l -u` (hidden by
  default: up-to-date, `LL`, ignored). `-u/--unused-patterns` early-returns
  with the report's stale block (header + `  !P  <pat>` lines); no unused
   patterns → silent exit 0. In `--porcelain` stale lines are appended only
   when the filtered entry list is empty. Any restrictive filter flag
   (`-c/-m/-U/-M/-p/-i`) suppresses the stale block in default reports AND the
   porcelain fallback (`report_stale` = empty slice at the Output stage);
   `--all` keeps the block (it widens, not restricts); scoped PATHS suppress
   via empty `stale_patterns` (Phase 3).

## Encryption (crypt.rs)

`encrypt_bytes`: builds a self-contained **DFMENC** (magic `DFMENC`,
`FORMAT_VERSION = 2`) blob. Public header: Argon2id KDF cost params
(`m_cost` KiB, `t_cost`, `p_cost`), 16-byte salt, 24-byte nonce. Key derived
with Argon2id (release: 64 MiB / t=3 / p=4; debug: 8 MiB / t=1 / p=1) over the
password; payload is **XChaCha20-Poly1305** AEAD where the encrypted plaintext
is `u32 metadata_len, metadata, content` — metadata carries the inner name,
file mode and a non-encrypted directory entry per enclosing directory (so a
pull restores e.g. a 0700 SSH dir). `decrypt_bytes` reads `m_cost/t_cost/p_cost`
**and caps them** (`m_cost ≤ 16 GiB`, `t_cost ≤ 10`, `p_cost ≤ 1024`) so a
crafted blob in a public repo cannot force an absurd Argon2 allocation on
`pull`. Wrong password / tampered ciphertext (`decrypt` returns
`WrongPassword`). Decryption retries once on a wrong password
(`decrypt_blob_with_retry`: clears the cache, prints `wrong password for
{:?}, please try again.` to stderr, re-prompts). The password cache is a
process-global `Mutex<Option<String>>`. `obtain_password`: if
`obtain_password_shell_command` is set, pipe it to `sh` **stdin** (not `-c`,
invisible in `ps`) and read stdout (`trim_end_matches(['\r','\n'])` so manual
decrypt works); else masked `rpassword` prompt. All notices go to **stderr**.
Streaming: peak RAM O(64 KiB chunk) regardless of file size (see README §4
"Memory use").

## Traversal (list_directory, lib.rs)

Walks each root with `WalkDir::filter_entry`; `rel_base` = where ignore
patterns are relative to (target or source dir). `TraversalFilter`:
`KeepMatching(&RegexSet)` (pull: keep rel-path matches — skips dot files AND
dot dirs) or `PruneIgnoredDirs(&RegexSet)` (add/forget/status/ignore: keep
every file, prune dirs whose subtree is fully ignored). A dir rel path `R` is
fully ignored iff component-wise matching hits `R + "/x"` (sentinel makes `R`
non-last). Root always kept (`depth()==0`) so a named ignored path is still
entered. Pruned dirs recorded in `ListDirectories::pruned`; `status` renders
each as one `!! dir/` entry. `filter_entry` never yields pruned entries → they
don't count toward progress. Rel = `strip_prefix(rel_base)` fallback
`strip_prefix(walk_root)`, else kept (no pruning). `follow_links(false)` +
`follow_root_links(false)`; WalkDir `NotFound` passes original path through;
directories skipped.

## Unreadable objects (permission/ownership)

`io::ErrorKind::PermissionDenied` (strict perms, wrong owner) is **skip-with-
warning**, never a command failure:
- `list_directory` (lib.rs) downgrades WalkDir `PermissionDenied` to a
  `warn!` naming the path (unlike `NotFound`, which passes the root through,
  and all other errors, which land in `errors` and fail the command).
- Analysis loops in add/pull/forget and `compare_files` in status/merge wrap
  per-file calls; task **execution** loops in add/pull also guard the actual
  copy/encrypt/symlink calls — a single unreadable object is skipped, remaining
  tasks still run.
- `DfmError::is_permission_denied()` (lib.rs) detects the variant; forget's
  delete phase was already best-effort.

## Gotchas / conventions

- **Symlink pointer postfix appends to the full filename**
  (`link-to-file.txt` → `link-to-file.txt.symlink`, not `link-to-file.symlink`).
- **Task pattern**: mutating ops are queued as task enums, executed in a final
  loop; `continue` in analysis doesn't cancel already-queued tasks.
- **State dispatch**: `forget` uses `with_state_even_if_error` (persist state
  even on failure); `add`/`pull`/`merge` use `with_state` (state only written
  on success). `status` runs on a read-only borrow of state.
- **`main_logic` resolves state/config as `Option`**: unresolvable paths log a
  warning and continue (relevant to `purge`/`paths` with `$HOME` unset); mutating
  commands then error via `with_state`.
- `source_rel_to_target_rel`/`resolve_source_variant`/`get_sync_time` live in
  **commands/mod.rs**, not lib.rs.
- `merge_tool_command`/`diff_tool_command` run directly (no shell) — `|`, `>`,
  `$VAR` don't work.
- main.rs requires the state file for add/pull/forget/merge/diff/status
  (`NotFound` otherwise); init/config/purge/ignore/paths work without it.

### Testing assertions: got-it-right rule

Assertions are **grep over captured output**. `set -eEu` aborts the test on a
failing command — but **only if that command is not negated with `!`**. POSIX
`-e` explicitly exempts "a command whose return value is inverted with `!`", so:

- **Positive** (must appear) → plain pipeline, aborts if not found:
  `dfm status 2>/dev/null | grep -qF "pat"` or `echo "$RES" | grep -qF "pat"`.
- **Negative** (must NOT appear) → **never** `! cmd | grep -qF` (that inverts
  the return and `set -e` skips it → mid-file asserts silently false-pass).
  Capture output first, then let the *grep itself* be the only command:
  `RES=$(dfm status 2>/dev/null); assert_fail grep -qF "pat" <<< "$RES"` —
  `assert_fail` just inverts the command status, so grep exiting 0 (text
  found) fails the test; grep exiting 1 (absent) passes it.
- **Expected-failure commands** → `run_fail dfm ...` (launcher.sh): asserts
  non-zero exit and captures combined output into `$FAIL_OUTPUT`; follow with
  `assert_succ grep -qF "msg" <<<"$FAIL_OUTPUT"`. Replaced all
  `set +e / rc=$? / set -e / err.txt` blocks (8 tests).
- Anywhere shell negation is needed use `if cmd | grep -qF ...; then exit 1; fi`
  or `assert_fail`, and position grep as the final (non-negated) pipeline step.
  The two `! grep` false-passes that violated this
  (test_traversal_skips_ignored_dirs.sh) were converted to `assert_fail`.

## Debug strategies (in order)

1. Run the failing test alone: `bash tests/launcher.sh test_x.sh` (already
   full `-x` trace). Read the failing assertion + lines above before touching
   code.
2. If trace shows success but wrong output, add **one** `eprintln!` at the
   point the asserted value is computed, print actual, compare to expectation.
3. Read the function end-to-end to form a hypothesis, confirm with 2.

| Symptom | Likely cause |
|---|---|
| `grep` 1 on `dfm status` | entry in hidden category (`LL`/`--`/`!!`/`!L`) — try `--all`/`--short` |
| `test -f` fails for pointer file | `.symlink` postfix appended to full filename |
| `assert_source` fails | dot-prefix/postfix/path-component mismatch in computed source path |
| queued task still runs after `continue` | tasks already queued execute in the final task loop |
